# Netopeer2 NETCONF benchmark

This profile uses the latest published Netopeer2 release checked on 2026-11-10: 2.8.21, with its corresponding libyang 6.4.13, libnetconf2 4.6.4, and sysrepo 5.2.27 dependencies. The official source archives and SHA-256 locks are bundled; the Docker build verifies each archive before compiling.

Netopeer2 exposes NETCONF over SSH on container port 830. AFLNet needs a raw TCP request stream, so a small in-container bridge accepts test traffic on 1830 and forwards each connection to the SSH `netconf` subsystem using a throwaway key created during image build. Only 127.0.0.1:1830 is published on the host; SSH port 830 is not published. The fuzzer, bridge, and server run in the same container. A compiled ELF target retries the SSH banner check, stays alive until AFLNet sends SIGTERM through `-K`, then checks the banner again and signals a testcase crash if the external server is unavailable. AFLNet’s `-c` hook runs `server-recover.sh` before the next testcase and restarts the local server only when the SSH health check fails; each recovery is recorded in that run’s `server-recoveries.log`. This keeps the external service lifecycle visible to the fuzzer instead of treating a one-shot readiness exit as a clean testcase.

The corpus uses NETCONF base:1.0 hello, a subtree-filtered `<get>` limited to `ietf-netconf-monitoring`, and `<close-session/>` requests framed with `]]>]]>`. The parser also recognizes NETCONF 1.1 chunk framing. The smoke test checks the SSH subsystem hello and a successful filtered monitoring-data reply; it does not fetch the full datastore. This is black-box state-feedback fuzzing; it does not report server source coverage.

Run `python3 generate_seeds.py`, `./build-aflnet.sh`, and `./build-image.sh` (which verifies package indices over certificate-checked HTTPS and pins the current verified Ubuntu security CDN node). Start the service with `./start-server.sh`, run `python3 protocol_smoke.py`, then start the 1,800-second campaign with `docker exec -d netopeer2-netconf-2821 bash /opt/benchmark/fuzz.sh /results/netconf-30m 1800`. Replay the resulting queue with `python3 replay_queue.py results/netconf-30m`. After verifying the independent ZIP and SHA-256 checksum, `./stop-server-and-remove-image.sh` removes this profile's exact container and image.

The local SSH test key is generated only inside the image for this isolated benchmark and must not be reused for other systems. Per-protocol framework experience is kept in the shared experience library, not repeated in this package.

The completed run and triage are documented in `ACCEPTANCE.md`. To repeat monitor-crash triage after a campaign, run `docker exec -i netopeer2-netconf-2821 python3 - < triage_crashes.py`; it replays each candidate three times, records only send/health outcomes in `results/netconf-30m/crash-triage.json`, and never stores raw replies. Experience rules stay in the shared `基准化经验库.md`.
