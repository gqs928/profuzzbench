# Memcached protocol benchmark acceptance checklist

Use `./acceptance.sh memcached-fuzz "$PWD/results/memcached-acceptance" 30m` in Kali after rebuilding the image. The script stops on the first failed required check, writes evidence into that result directory, computes `SHA256SUMS`, and creates a `.tar.gz` bundle beside it. A 60-second `validate.sh` run is only a preflight, not the long-run acceptance.

| # | Item | Required pass condition | Evidence generated by the full run |
|---|---|---|---|
| 1 | Target reproducible | Pinned Ubuntu image digest, dated Ubuntu package snapshot, pinned AFLNet and Memcached commits; fresh image builds from the project Dockerfile | `build-logs/docker-build.log`, `build-versions.txt`, `image-id.txt`, `build-input-sha256.txt`, `source-snapshot/` |
| 2 | Protocol behavior preserved | Same normal ASCII/TCP requests get equivalent responses from unmodified reference and AFL-instrumented target; volatile stats values checked semantically | `protocol-smoke.log`, `protocol-smoke/*.response`, `protocol-smoke/summary.txt` |
| 3 | Seeds reach business states | Valid CRLF corpus includes byte-counted storage bodies; `set → get → delete → get` reaches `STORED`, `VALUE`, `END`, `DELETED`, `END` | `source-snapshot/seeds/`, image `in-memcached/`, ten replay transcripts under `repeatability/` |
| 4 | State feedback is real | AFLNet's `-P MEMCACHED -E` uses the request/response adapter; the run explores at least two states and one edge | `fuzz.log`, `fuzz/ipsm.dot`, validated `fuzz/ipsm.plain`, queue and replayable paths |
| 5 | Coverage is credible | Independent gcov build is replayed from the AFLNet queue; line/branch series and detailed source report are nonempty; `memcached.c`, `proto_text.c`, `proto_parser.c`, and `items.c` report executed lines | `coverage.log`, `coverage-core-files.txt`, `fuzz/cov_over_time.csv`, `fuzz/cov_html/index.html` |
| 6 | Every round resets | Ten fresh gcov-server processes replay the exact same business seed with identical protocol-state sequence and response bytes; aggregate line and branch coverage each vary by no more than 0.5 percentage points across runs. Raw `.gcda` hashes are retained as diagnostics, not required to be byte-identical; AFLNet uses `-K` for per-test server cleanup | `repeatability/repeatability.csv`, ten `.response` and `.server.log` files, `fuzz/fuzzer_stats`, `variable-paths.txt` |
| 7 | Abnormal exits observable | Disposable test-only preload deliberately aborts on `CRASHNOW`; AFLNet records it and the saved sample causes the same abnormal exit on replay. Normal binaries and source remain unmodified | `crash-injection/fuzzer.log`, `crash-injection/controlled-crash.sample`, `crash-injection/replay.log`, `crash-injection/summary.txt` |
| 8 | Results reviewable | Independent run parameters, source/build identity, corpus, queue, crashes/hangs, IPSM, coverage CSV/HTML, reset logs, crash test, and file checksums are retained | `acceptance-summary.txt`, `build-versions.txt`, `fuzz/`, `protocol-smoke/`, `repeatability/`, `crash-injection/`, `SHA256SUMS`, result archive |

## Interpreting the outcome

The script reports `PASS` only for checks it can verify. It also records AFLNet's `variable_paths`; if nonzero, use `variable-paths.txt` and the matching queue files to investigate whether the variability came from dynamic protocol behavior or incomplete reset. The separate ten-run seed test must still be byte-for-byte/coverage-counter stable for item 6 to pass.

No fuzzing campaign can promise that the target has no defects. `unique_crashes=0` means none was observed in that run; item 7 instead tests that the harness detects and reproduces one deliberately injected, isolated test crash. Remove the test hook by ending its disposable container; it is not part of the normal Memcached build.

The earlier AFLNwe-only 30-minute output and gcovr screenshot predate the state parser. They are preliminary evidence only and must not be substituted for the AFLNet `-P MEMCACHED -E` run and IPSM graph required by item 4.
