# OpenLDAP LDAP benchmark

Target: OpenLDAP 2.7.2, the upstream current Feature Release checked 2026-11-10; 2.6.16 is the separately maintained current LTS line. This baseline chooses the latest stable feature release. The official 2.7.2 source signature is verified with the OpenLDAP Project key (fingerprint `3CE269B5398BC8B785645E987F67D5FD1CE1CBCE`), and the SHA-256 is locked in `source-lock.json`. Run `./verify-source.sh` before the image build. The build bootstraps certificate-verified HTTPS to Ubuntu apt with a SHA-256-locked bundle of public Mozilla roots, then installs Ubuntu `ca-certificates`; Ubuntu archive signatures remain verified by apt.

`Dockerfile` builds that source and embeds the BER-aware AFLNet binary. It installs Ubuntu `groff-base` for OpenLDAP release man-page generation (`soelim`). `slapd` listens on container TCP 3389, published only to host loopback as 127.0.0.1:1389; AFLNet runs in the same container and connects to 3389. A statically linked ELF readiness probe is used as AFLNet's process target while slapd remains a managed persistent service. The suffix is `dc=example,dc=com`; the corpus exercises anonymous Bind and a base-object RootDSE Search.

Run `./build-aflnet.sh`, `./verify-source.sh`, run `./build-image.sh`, then `./start-server.sh`. The build script pins the security.ubuntu.com hostname to the current verified official CDN IPv4; override `OPENLDAP_SECURITY_CDN_IPV4` if that address rotates. Run `python3 protocol_smoke.py` from the host and start the 1,800-second campaign with `docker exec -d openldap-ldap-272 bash /opt/benchmark/fuzz.sh /results/ldap-30m 1800`. Replay with `python3 replay_queue.py results/ldap-30m`. After package and checksum verification, `./stop-server-and-remove-image.sh` removes only this profile's container and image.

No UnbindRequest is used because Unbind has no LDAP response. Truncated BER remains in fixtures, not the live seed corpus. Per-protocol experiences belong in the shared experience library.
