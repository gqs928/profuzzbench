# Openfire XMPP benchmark

A reproducible AFLNet dumb-mode response-state benchmark for Openfire 5.1.2 over loopback XMPP client-to-server TCP on port 5222. It reuses the XMPP request-boundary and response-tag adapter from the ejabberd profile. The broker runs from the official Openfire release distribution with embedded database demo boot; the administrative console is disabled and the XMPP domain is `example.test`.

The profile is black-box and does not report Openfire Java source coverage. AFL bitmap counters are not source coverage. The formal default campaign duration is 1,800 seconds after the first executed test case. Queue replay is a connectivity/response inventory, not an independent coverage run. Run `protocol_smoke.py` against a started container before the campaign. Build with `docker build -t profuzzbench-openfire:5.1.2 .`, run the smoke container with `docker run --rm -d --name openfire-smoke profuzzbench-openfire:5.1.2`, then use `docker exec openfire-smoke python3 /opt/benchmark/protocol_smoke.py`. For the formal run, mount an empty host results directory at `/results` and invoke `docker run --rm --name openfire-campaign -v "$PWD/results/xmpp-30m:/results/xmpp-30m" profuzzbench-openfire:5.1.2 bash /opt/benchmark/fuzz.sh /results/xmpp-30m 1800`.
